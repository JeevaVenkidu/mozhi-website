# Security Policy

We take the security of Mozhi and its web properties seriously. If you discover a security vulnerability in the Mozhi website or extension, we appreciate your help in disclosing it responsibly.

---

## Supported Versions

Only the latest commit on the `main` branch of this repository is actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |
| < 0.1.0 | :x:                |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or social media.**

To report a vulnerability privately:

1. **GitHub Private Vulnerability Advisory (Preferred)**:
   Navigate to the repository's **Security** tab on GitHub and click **"Report a vulnerability"** to submit an advisory draft directly to the maintainer.
   
2. **Direct Contact**:
   If Private Vulnerability Reporting is unavailable, please contact the maintainer directly:
   - GitHub Profile: [@JeevaVenkidu](https://github.com/JeevaVenkidu)
   - Security Contact: `[INSERT SECURITY CONTACT EMAIL OR LEAVE GITHUB CONTACT ONLY]`

### What to Include in Your Report

To help us investigate and resolve the issue quickly, please provide:
- A description of the vulnerability and its potential impact.
- Clear steps to reproduce the issue (including proof-of-concept scripts or screenshots where applicable).
- The affected component, file, or endpoint.
- Any suggested remediation if known.

---

## Handling & Disclosure Process

- We will acknowledge receipt of your vulnerability report as soon as possible.
- Once confirmed, we will work on a fix in a private branch before deploying the patch.
- We will coordinate public credit and disclosure with you once the fix has been verified and released.
